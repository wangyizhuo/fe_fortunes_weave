# 检查规则：Yizhuo 怎么检查产出 → 程序里的哪一项

过去两周 Yizhuo 检查成长规划的方式，归纳成 9 种。每种背后的意图，和 `levelup/rng/checks.py` 里对应的自动检查如下。
`bash build.sh` 每次都会跑全部检查，任何一项不过就不发布页面。

| # | Yizhuo 的检查方式（原话举例） | 背后的意图 | 自动检查 |
|---|---|---|---|
| 1 | 拿游戏里实际升级对照预测：「实际升级和你的种子预测对不上」「米迦现在 22」「伊欧是 Lv23 轻骑兵，不是战车么」 | 预测必须以真实状态为起点，种子一步都不能错 | **D1** 回测每条记录；**D2** 起点 = 截图等级/职业；**D6** 种子链连续；**D7** 能力/技能/等级合理 |
| 2 | 逐级追问选择：「22-23 为什么选 15 分而不是 16 分」「杨界有一级用平民更高但没选」 | 每一级都用最好的已有职业，例外必须有理由 | **P5**（不是最高分就要写明均衡/体格原因；同分取级别高的） |
| 3 | 追问考试和跳过：「艾丝 31 级为什么跳过」「米迦为什么要考诅咒师，这个算法不对吧」「后面没用这个职业，就写跳过」 | 每次考试/跳过都按规则、值得；考了的职业要用 | **P6** 跳过符合跳过条件；**P8** 考的职业至少用一级；**P9** 去掉任何一个考试都不会更好；**P12** 换 1～2 个职业的任意组合都不会好 1 分以上 |
| 4 | 指定硬规则：迪必考恶棍、不要重装；法必考萨满；「保留迪 Lv25、Lv31 那个种子」「Lv45 每人只转一次上级」 | 定过的规则以后每次都遵守 | **P3** 必考/排除；**P7** 保留的种子；**P11** 上级只一次；**P1** 职业先拿到再用、考试按种子能过 |
| 5 | 要求所有人一视同仁：「保证所有角色的生成逻辑都一样」「Fabio 每级为什么没有像迪一样显示所有职业」「所有职业都要考虑并且列出」 | 没有给某个人手调的特例 | **P4** 同一套 17 个职业；**U3** 每级列出全部职业；**U5** 加点相同的职业全列 |
| 6 | 要数字不要形容：「不讲成长率，只讲具体的数值区别」「展示具体的数值差距，包括差值和净值」「每个考试都要显示通过概率」 | 能直接比较、自己判断 | **U2** 每个考试/跳过有判定值和成功率、每级四种走法；**U4** 比较都给每项 ± 和净值 |
| 7 | 抓前后不一致：「页面 171 你说 174」「确定全部都更新好了么」「为什么迪线还有技能没确认」 | 页面、回复、表格说的是同一个数，没有过时内容 | **U1** 页面 = 规划器；**P10** 合计口径一致；**U6** 没有过时/坏掉的文字；**U8** 手写说明不写数字 |
| 8 | 用词：「使用我要求的术语」「不要用考试这种 ambiguous word」 | 正常 / 转职 / 考试 / 跳过 四个词固定含义 | **U7** 四个词在页面上统一；**U6** 禁用旧说法 |
| 9 | 要求规则固化：「所有的规则都应该固化在程序里，用数据 + 程序生成」「找一个地方记录我所有的决定」「数据都存一份并有校验」 | 换一个线程也能得到一样的结果；改了什么看得见 | **D3** 基础数据齐全；**D4** decisions.json 格式和代码位置；**D5** data/ 可读副本是最新的；**D8** 吃饭喜好表完整；**G1** 结果快照（变了就列出每人变了什么） |

## 还没法自动检查的（要人工）

- **中/英/日三语资料都查过再回答**（Yizhuo 10-30）：这是回答问题时的流程，程序检查不到。每次回答要说明查了哪些站。
- **游戏里的真实结果**：考试成功率（`exam_chance.json`）只有截图里看到的几个，其余是按技能等级估计；训练到能考需要几回合没有算进成本（现在每段 0.5 分是估计）。
- **装备、友好度**：程序和表格里都还没有这些数据，`data/` 里留空。
- **网页交互**（勾选、同步到主表）：`check_layout.js` 只查排版，不点按钮。

## 检查发现过的问题（11-11 加检查时）

- 「我的决定」表有几条显示成空行（decisions.json 格式不统一）→ D4 + 统一格式
- 页面还有「随便考」等旧说法 → U6
- 选择表里「挂了少 0 分」算错（成功率被考前训练规则过滤掉了）→ 修 make_choices
- 手写说明还停在 11-05 的旧路线 → U8，说明里的数字改成程序生成
- 优先级名单在两个地方各写一份 → 统一到 `run_plans.tier_of`
- 已知差异（不算错）：米迦「猎兵 + 诅咒师」净值比现在的「弓箭手」高 0.2 分，在训练成本的误差内，Yizhuo 已定考弓箭手（P12 容差 1 分）

## 改规则时

1. 改 `run_plans.py` / `planner.py`，在 `decisions.json` 记日期、范围、规则。
2. `bash build.sh`。G1 会打印每人路线、分数变了什么。
3. 确认变化是想要的，`python3 checks.py --update-golden`，把变化告诉 Yizhuo。
4. 如果是新的检查方式（Yizhuo 用新方法挑出了问题），在 `checks.py` 加一项 `@check`，并在上表加一行。
